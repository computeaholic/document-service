Domain Concept:
Controlled document approval workflow.

One entity:
Document

Fields:
- id (UUID)
- title
- content
- status (enum)
- version (int for optimistic locking)
- created_at
- updated_at

---

Valid States:
- draft
- submitted
- approved (terminal)
- rejected (terminal)

Valid Transitions:
draft → submitted (content must be non-empty)
submitted → approved
submitted → rejected

Illegal transitions:
- approved → anything
- rejected → anything
- draft → approved
- draft → rejected

Illegal transitions raise explicit domain exceptions.
Illegal transitions must be tested.

---

Endpoints:

POST   /documents              → create draft (idempotent via idempotency key)
GET    /documents/{id}         → retrieve
PUT    /documents/{id}         → update draft (optimistic lock)
POST   /documents/{id}/submit  → submit
POST   /documents/{id}/approve → approve
POST   /documents/{id}/reject  → reject

Error envelope required:
{
  "error": {
    "code": "machine_identifier",
    "message": "human readable"
  }
}

No raw exceptions returned.

---

Concurrency Model:
- Optimistic locking via version column
- Version mismatch returns 409
- IntegrityError mapped deterministically
- Duplicate idempotency key returns 409
- Concurrency tests required

---

Transaction Model:
All mutations use:
with session.begin():

No implicit commits.
No hidden side effects.
Multi-step state changes atomic.
